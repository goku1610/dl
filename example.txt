Hierarchy Implementation During Fine-Tuning
Two-Part Implementation:
1. Training Loss (Fine-Tuning Phase)
loss = loss_attr + 0.5 * loss_hier + 0.5 * loss_ctr
Hierarchical Consistency Loss:
Creates a binary mask of valid fine classes for each sample's true coarse class
Computes fine-class probabilities: fine_probs = softmax(fine_logits)
Penalizes probability mass on invalid fine classes:
  invalid_prob_mass = (fine_probs * (1 - valid_mask)).sum()
Weight: 0.5 (added to total loss during backprop)
2. Inference Constraint (Evaluation/Prediction)
Predict coarse class first
Lookup valid fine classes: coarse_to_fine_mapping[coarse_pred]
Mask out invalid fine classes (set to 0)
Renormalize and pick highest valid probability

what is this

Contrastive Loss Hyperparameters Explained
Temperature: 0.07
What it is:
A scaling factor applied to similarity scores before softmax: exp(similarity / temperature)
What it does:
Lower temperature (0.07) → sharper distinctions between positive and negative pairs
Makes the model more confident: strongly pushes matched image-text pairs together, strongly pushes mismatched pairs apart
Why 0.07:
Standard value from CLIP/contrastive learning literature
Too high (e.g., 1.0): soft, diffuse similarities → weak learning signal
Too low (e.g., 0.01): over-confident, unstable gradients
0.07 balances discrimination and gradient stability
Projection Dimension: 384
What it is:
Dimensionality of the shared embedding space where images and text are compared
Architecture:
Image (backbone) → 192/320-D → MLP projection → 384-D embeddingText (sentence-transformer) → 384-D embedding
Why 384:
Matches text encoder output: Your sentence-transformers model outputs 384-D embeddings natively
Computation efficiency: Smaller than backbone dimensions, reduces parameters
Sufficient capacity: 384-D captures rich semantic information for product attributes
Standard practice: Common projection size in vision-language models (CLIP uses 512)
How They Work Together:
# Image embeddings: [batch, 384]# Text embeddings:  [batch, 384]similarity = (img_emb @ txt_emb.T) / temperature  # [batch, batch]loss = cross_entropy(similarity, targets)
384-D ensures images and text live in the same semantic space
0.07 temperature makes the model confidently distinguish between matching and non-matching pairs
Result: Images with similar attributes cluster near semantically related text descriptions, enabling text-based product retrieval! 🔍

Here’s the rationale behind each training choice, keeping things grounded in common deep-learning practice:
Epochs = 60: Enough full passes for convergence without excessive overfitting or compute cost. Empirically, models tend to plateau around this range for similar setups, so it’s a practical middle ground.
Batch size = 64: Balances gradient noise and memory usage. Large enough for stable updates and good throughput on typical GPUs, small enough to fit mixed precision activations comfortably.
Optimizer = AdamW: Combines Adam’s fast convergence with decoupled weight decay for better generalization than classic Adam—especially important when using high weight decay.
Base LR = 1e‑4 with weight decay = 5e‑2: Low LR avoids divergence with AdamW and large batches, while relatively strong weight decay combats overfitting by discouraging large weights; this pair works well for modern transformer-style models.
Cosine schedule + 1 warmup epoch: Cosine decay steadily reduces LR, giving smoother convergence. Short warmup prevents instability at the start when weights are still adapting from random init or partial freeze.
Freeze first 2 epochs: Keeps lower layers fixed initially so the head or high-level blocks adapt without forgetting already-learned low-level features—useful when fine-tuning or when early layers are sensitive.
Mixed precision enabled: Cuts memory use and speeds up training via tensor cores, enabling batch 64 without loss in final accuracy (thanks to loss scaling).
DataLoader workers = 0, pin memory = True: Worker 0 avoids multiprocessing overhead/instability often seen in notebooks or constrained environments. Pinning memory still speeds GPU transfers even with a single worker, minimizing the loader bottleneck.
Each choice is about balancing stability, generalization, and practical hardware constraints rather than chasing theoretical optima.

Key limitations of the model in main_notebook2.ipynb
Data & label limitations
Fine classes are many but thinly populated: 186 fine-grained classes over ~11.8k images means relatively few examples per class, so per-class metrics are noisy and some rare categories are likely underfit despite using all eligible classes.
Label noise in attributes and coarse labels: attributes include misspellings and merged fields (e.g. "color, conidition, color containing full “color,size,condition,material” strings), and coarse labels are derived via simple string heuristics, so the supervision the model sees is imperfect.
Single-label assumption: each image is treated as belonging to exactly one coarse and one fine class, so the model cannot naturally handle multi-object or multi-label images.
Modeling & training limitations
Backbone capacity and diversity: only two relatively small vision transformers are used (DeiT-Tiny, TinyVIT‑5M); larger or different architectures (larger ViTs, ConvNeXt, CLIP-like models) are not explored, so we don’t know if performance is bottlenecked by model capacity.
Partial use of discovered attributes: the dynamic parser finds many facets (pattern, style, shape, features, etc.), but the unified model only predicts a fixed subset (coarse_class, fine_class, color, material, condition, size), leaving potentially useful information unused.
Limited handling of class imbalance and hard examples: there is no explicit re-weighting, focal loss, or sampling strategy for rare fine classes, and no curriculum or hard-example mining, which likely hurts performance on the tail.
Retrieval and contrastive learning limitations
Dependence on caption quality: the contrastive loss and text-to-image retrieval rely on whatever captions are present in Dataset.csv; if captions are short, missing, or noisy, the learned joint embedding space is suboptimal.
Simple retrieval strategy: retrieval is pure cosine similarity on static embeddings with no cross-attention re-ranking, query expansion, or user-feedback loop, so it may struggle on subtle or very compositional queries.
Evaluation & analysis limitations
Limited robustness checks: the notebook evaluates accuracy/F1 on an i.i.d. test split but does not test robustness to occlusion, lighting changes, domain shift, or out-of-distribution images.
No probability calibration or threshold tuning: although calibration curves and confidence analyses are plotted, there is no calibration method applied (e.g. temperature scaling), so predicted probabilities are not guaranteed to be well-calibrated for decision-making.
Interpretability is shallow: there are embedding visualizations (PCA/t‑SNE) and error breakdowns, but no localized explanations like Grad‑CAM or attention rollout, so we cannot see where in the image the models are focusing when predicting.
